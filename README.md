# Тепловыделение в бериллиевой мишени DARIA

Расчёт распределения энерговыделения на стенке теплосъёма бериллиевой болванки
по трекам частиц из GEANT4/SRIM: от точек энерговыделения в CSV до карты
тепловой нагрузки в СИ, готовой к импорту в COMSOL или ANSYS.

Стенка теплосъёма перпендикулярна оси пучка, поэтому искомая величина —
поверхностная плотность энерговыделения на плоскости Y/Z, то есть объёмное
энерговыделение, проинтегрированное вдоль оси пучка:

```
q(y, z) = ∫ ε(x, y, z) dx        [Вт/см², Дж/мм², ...]
```

### Исходные данные

Вход расчёта — готовые CSV с точками энерговыделения. Сами парсеры логов GEANT4 и
экспорт в CSV живут вне этого репозитория; здесь цепочка начинается с `.csv`.

Папки: `Effective traks/` — треки, обрезанные по замедлению протонов до 4.2 МэВ
(порог реакции ⁹Be(p,n)); `Full traks/` — полная толщина мишени.
Нужны колонки `x_mm, y_mm, z_mm, energy_deposition_mev`, отдельными файлами
для первичных и вторичных частиц.

## Методика расчёта

1. **Вокселизация.** CSV читается чанками, точки энерговыделения раскладываются
   в трёхмерную гистограмму `H[x, y, z]` = сумма dE в вокселе, МэВ на `n_sim_protons`
   протонов симуляции. Сетка строится по фактическому охвату данных, поэтому
   у первичных и вторичных частиц размер вокселя свой — он печатается и пишется
   в паспорт расчёта. Результат кешируется на диск: повторный прогон с другими
   параметрами пучка CSV не перечитывает.

2. **Нормировка на один протон.** `ε = H / (n_sim_protons · dV)` — МэВ на мм³ на
   один протон. Дальше всё линейно масштабируется параметрами пучка.

3. **Общая решётка болванки.** Карта переносится на решётку с единым шагом
   (точное перераспределение по площади, сумма сохраняется) и дополняется нулями
   до размера болванки. Общая решётка у первичных и вторичных означает, что их
   карты складываются напрямую, без пересетки.

4. **Свёртка с профилем пучка.** Исходный расчёт сделан для точечного пучка на оси,
   поэтому реальное распределение получается свёрткой с поперечным профилем —
   эллиптическим гауссом σ_y × σ_z. Ядро считается как точный интеграл профиля
   по бину (через erf), нормировка — на полный гаусс: хвост, ушедший за край
   болванки, честно теряется и виден в балансе энергии.

5. **Движение мишенной сборки.** Колесо с несколькими болванками вращается, и за
   время импульса болванка смещается поперёк пучка вдоль оси `y` на `L = v·τ`.
   В системе отсчёта болванки центр пучка равномерно проезжает отрезок `L`, поэтому
   профиль пучка — свёртка гаусса с равномерным распределением. Для неё есть
   замкнутая форма через `Ψ(x) = x·Φ(x) + φ(x)`, так что движение учитывается тем же
   единственным ядром свёртки и не стоит ничего по времени.

   Предельная скорость определяется условием, что в начале и в конце импульса центр
   пучка отстоит от края болванки не меньше чем на `edge_margin_sigma · σ_y`
   (чтобы пучок не задевал держатели):

   ```
   L_max = 2·(R − k·σ_y),      v_max = L_max / τ
   ```

   Для R = 25 мм, σ_y = 3.33 мм, k = 5, τ = 100 мкс: L_max = 16.7 мм, **v_max = 167 м/с**.
   При меньшей скорости зазоры больше, при превышении печатается предупреждение.

6. **Масштабирование под пучок.** Число протонов за импульс `N = I_имп·τ/e`,
   энергия за импульс `E = ε·N·(1 МэВ в Дж)`. Мощность получается делением энергии
   на интервал усреднения — см. раздел «Энергия и мощность».

7. **Проекция и суммирование.** Карта интегрируется вдоль оси пучка, первичные и
   вторичные складываются, всё за пределами круга болванки обнуляется.

8. **Полярные координаты и сохранение.** Карта переводится в (r, φ) для круглой
   болванки, считается азимутально усреднённый профиль, результат сохраняется
   в `.npz` (сетки + карты + профили) и `.json` (все параметры и балансы).

### Почему это быстро и помещается в память

Расширенная трёхмерная карта на болванку Ø50 мм заняла бы около 3 ГБ. Она не нужна:
свёртка по (y, z) и интегрирование по x линейны и коммутируют, поэтому

```
Σ_x ( H[x] * K )  ≡  ( Σ_x H[x] ) * K
```

Сначала карта схлопывается по x (нативная сетка 100³ = 8 МБ), затем один раз
свёртывается двумерная карта, причём как `full`-свёртка компактного блока с ядром
размером с болванку — массив размера болванки создаётся ровно один раз.
Разрешение при этом не теряется, а шаг `dx` в формуле вообще сокращается: ответ
от разрешения по оси пучка не зависит. Пик памяти — около 200 МБ, расчёт 0.2–3 с.

### Контроль правильности

* Баланс энергии: интеграл карты по площади совпадает с ΣdE из CSV с точностью
  до потерь за краем болванки, которые печатаются отдельной строкой (`10⁻¹³` в базовом случае).
* Быстрый путь сверен с наивным («расширить 3D → свернуть каждый срез → сложить»):
  интеграл совпадает до 10⁻⁷, сдвиг центроида < 10⁻⁶ мкм.
* Независимость от разрешения по оси пучка: при `bins` по x от 10 до 150 результат
  совпадает бит-в-бит.
* Ядро движения сверено с прямым усреднением статической карты по 2001 положению
  вдоль траектории: совпадение до 4·10⁻⁴.

## Параметры

### Данные и нормировка

| Параметр | CLI | По умолчанию | На что влияет |
|---|---|---|---|
| `PRIMARY_CSV` | `--primary` | — | CSV с dE первичных частиц (обязателен) |
| `SECONDARY_CSV` | `--secondary` | нет | CSV с dE вторичных; без него считаются только первичные (для 20 МэВ вторичные дают +3.8 %) |
| `N_SIM_PROTONS` | `--n-sim` | 10000 | число протонов в симуляции. **Вся абсолютная шкала обратно пропорциональна ему** |
| `BINS` | `--bins` | 100 100 100 | воксельная сетка по данным. По x на результат не влияет, по y/z задаёт нативное разрешение |

### Пучок (`BeamParams`)

| Параметр | CLI | По умолчанию | На что влияет |
|---|---|---|---|
| `sigma_y_mm` | `--sigma-y` | 3.33 | ширина пучка вдоль движения сборки. Через неё же считается требуемый зазор до края |
| `sigma_z_mm` | `--sigma-z` | 2.66 | ширина пучка поперёк движения |
| `peak_current_mA` | `--current-mA` | 100 | ток **в импульсе**. Линейно масштабирует всё энерговыделение |
| `pulse_us` | `--pulse-us` | 100 | длительность импульса. Линейно масштабирует энергию за импульс и задаёт путь болванки `L = v·τ` |
| `rep_rate_Hz` | `--rep-Hz` | 100 | частота источника. Влияет только на мощности, не на энергию за импульс |

Меньшая σ — выше пик при той же полной мощности. Мощность в течение импульса от
`rep_rate_Hz` не зависит, средняя — зависит линейно.

### Мишенная сборка (`TargetParams`)

| Параметр | CLI | По умолчанию | На что влияет |
|---|---|---|---|
| `diameter_mm` | `--diameter` | 50 | диаметр болванки: размер расчётной области и предельная скорость |
| `speed_m_per_s` | `--speed` | 0 | скорость движения сборки поперёк пучка. Размазывает распределение вдоль `y` на `L = v·τ`; полная энергия не меняется, пик падает |
| `n_pucks` | `--n-pucks` | 1 | число болванок на колесе. В одну болванку импульс приходит с частотой `rep_rate / n_pucks`, поэтому **делит все средние величины**. На энергию за импульс не влияет |
| `edge_margin_sigma` | `--edge-margin-sigma` | 5 | требуемый зазор от центра пучка до края болванки, в единицах σ_y. Задаёт предельную скорость |

Скорость и пиковая нагрузка (20 МэВ, Ø50 мм, базовый пучок):

| v, м/с | 0 | 50 | 100 | **167** | 200 |
|---|---|---|---|---|---|
| путь за импульс, мм | 0 | 5.0 | 10.0 | **16.7** | 20.0 |
| зазор, σ_y | 7.5 | 6.8 | 6.0 | **5.0** | 4.5 ⚠ |
| пик, Вт/см² | 22 525 | 20 578 | 16 300 | **11 125** | 9 378 |

## Энергия и мощность

Исходная физическая величина одна — **энергия, выделившаяся за один импульс**.
Мощность получается делением на интервал усреднения, и таких интервалов три:

| # | Интервал | Что получается | Для чего |
|---|---|---|---|
| 1 | длительность импульса `t` | мощность в течение импульса | нестационарный расчёт внутри импульса, пиковые термонапряжения |
| 2 | период источника `T = 1/f` | мощность на всю сборку | баланс теплосъёма колеса целиком |
| 3 | `N·T` (N — число болванок) | мощность на одну болванку | стационарная температура конкретной болванки |

Вариант 1 больше варианта 2 в скважность `S = T/t = 100` раз
(коэффициент заполнения `D = t/T = 1 %`). Вариант 3 меньше варианта 2 в `N` раз.
При `n_pucks = 1` варианты 2 и 3 совпадают.

**Карты в `.npz` и вся выгрузка для COMSOL/ANSYS нормированы по варианту 3.**

Базовый случай (20 МэВ, Effective, 10000 протонов, 100 мА × 100 мкс × 100 Гц, N = 1):

```
энергия за импульс              125.449 Дж   (первичные 120.902 + вторичные 4.547)
1) за 100 мкс                  1 254.49 кВт
2) за период 10 мс               12.5449 кВт
3) за оборот колеса (N = 1)      12.5449 кВт
пик на стенке (v = 167 м/с)   111.25 Дж/см² → 1.112 МВт/см² → 11 125 Вт/см²
```

## Как запускать

### Обычный путь

Открыть `run_wall_load.py`, поправить блок `ПАРАМЕТРЫ` сверху и запустить:

```bash
python run_wall_load.py
```

Скрипт печатает предельную скорость сборки, паспорт расчёта, баланс энергии и все
три мощности, сохраняет `results/<имя>.npz`, `.json` и `.png`.

### Командная строка

```bash
python beam_heat_load.py \
    --primary "Effective traks/primary_de_points_20_MeV.csv" \
    --secondary "Effective traks/secondary_de_points_20_MeV.csv" \
    --units W/cm3 --speed 167 --n-pucks 8 --output-step 0.25 \
    -o results/wall_load_20MeV
```

Полный список ключей: `python beam_heat_load.py --help`.

### Из ноутбука или своего кода

```python
from beam_heat_load import BeamParams, TargetParams, Config, compute_wall_load, plot_wall_load

res = compute_wall_load(Config(
    primary_csv="Effective traks/primary_de_points_20_MeV.csv",
    secondary_csv="Effective traks/secondary_de_points_20_MeV.csv",
    beam=BeamParams(sigma_y_mm=3.33, sigma_z_mm=2.66),
    target=TargetParams(diameter_mm=50.0, speed_m_per_s=167.0, n_pucks=8),
    units="W/cm3",
    output="results/wall_load_20MeV",
))
plot_wall_load(res, zoom_mm=20)
```

### Чтение результата

`read_wall_load.ipynb` — поменять путь `NPZ` и выполнить. Ноутбук печатает паспорт
расчёта, проверяет баланс энергии, строит карту и профили и выгружает в `export/`
файлы для COMSOL (`Interpolation` в формате Grid) и ANSYS (`External Data`),
все в СИ. Там же расписано, как подключить их в обоих пакетах.

## Допущения и ограничения

* Учитывается энерговыделение **первичных и вторичных заряженных** частиц.
  Нейтроны и гамма-кванты уносят энергию из мишени и в источник не входят.
* Пучок параллельный (расходимость не учитывается), профиль гауссов,
  ось пучка проходит через центр болванки.
* Движение сборки — равномерное смещение вдоль `y`, траектория отцентрована
  на болванке. Кривизна траектории не учитывается: стрелка дуги `L²/(8R_колеса)`
  меньше 0.2 мм даже при радиусе колеса 0.2 м, против σ_y = 3.33 мм.
* Поперечное распределение считается не зависящим от глубины: если нужен объёмный
  источник, он восстанавливается как `Q(x,y,z) = q(y,z)·f(x)`, где `f` — нормированная
  форма `dE/dx` (лежит в `.npz` как `lin_depth_total`). Полное трёхмерное поле по
  трекам не сохраняется.
* Расчёт привязан к конкретной толщине мишени и энергии протонов: они определяются
  тем, какой CSV подан на вход.
